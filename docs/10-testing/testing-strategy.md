# Testing strategy

Current evidence is one Spring application-context test in each of `account` and `person`. The full Maven test run currently fails while creating the Person application context: `InstitutionalCustomerRepository.findByStudentOrMemberCountGreaterThan` references a `student` property that is not present on `InstitutionalCustomer`. There are no visible unit, mapper, repository integration, controller, contract, end-to-end, Testcontainers, Kafka, performance, or security tests. Build a pyramid: fast unit tests for business rules/services; mapper tests for mappings/null policies; repository integration tests against PostgreSQL; controller tests for validation and error behavior; API contract tests; end-to-end tests through deployment; and targeted performance/security tests. Mock network boundaries, not the domain logic under test.
