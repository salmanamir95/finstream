# Testing strategy

Current evidence is one Spring application-context test in `account` and two tests in `person`. The Person tests now cover application startup plus representative inherited repository-fragment queries across individual, organizational, and business repositories. The clean Person test and full Maven reactor pass against the configured local PostgreSQL databases. There are no visible unit, mapper, repository integration, controller, contract, end-to-end, Testcontainers, Kafka, performance, or security tests. Build a pyramid: fast unit tests for business rules/services; mapper tests for mappings/null policies; repository integration tests against PostgreSQL; controller tests for validation and error behavior; API contract tests; end-to-end tests through deployment; and targeted performance/security tests. Mock network boundaries, not the domain logic under test.
