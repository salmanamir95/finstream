# Contribution guide

Use short-lived branches and Conventional Commit-style messages (`feat:`, `fix:`, `refactor:`, `docs:`, `test:`, `chore:`). A PR should state behaviour, migration/API/security impact, tests, and rollback considerations. Reviewers check validation, transaction boundaries, ownership, errors, logging redaction, mapper effects, and backward compatibility.

Definition of Ready: business rule, owner, API expectation, and acceptance tests are understood. Definition of Done: reviewed code, tests, migration and docs updated, security/observability implications addressed, and deployment/rollback path known.
